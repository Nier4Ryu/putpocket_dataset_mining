# Remote Server-B workspace handoff

## Outcome

Implemented the canonical Server-A / Server-B execution split. Server-A owns inference/controller work and does not require local Docker. Server-B owns a persistent isolated agent workspace through the dedicated `putpocket-remote-workspace` wrapper and separately owns hidden verification/Judge through `putpocket-remote-verifier`.

## Architecture

- Accepted decision: `agent/decisions/D20260812-002__server-a-server-b-distributed-execution.md`.
- Workspace backend: `ssh_remote_docker` (legacy `remote_ssh_docker` remains accepted).
- Workspace and verifier use independent remote configs, wrappers, and roots while sharing the approved SSH endpoint/route.
- Workspace commands arrive as JSON and are executed only through `docker exec` in the named session container.
- Session state persists across tool calls; snapshots are created under the session for verifier staging.
- RunPod profile maps generic `server_a` / `server_b` roles to RunPod / Server-1 and uses `/root/.ssh/pod_id_rsa` with strict known-hosts.
