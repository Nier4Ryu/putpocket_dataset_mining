# Advisory Lock Queue Control Handoff

## Objective

CODE_CONFIRMED: Added local Agent advisory locking so concurrent Agents coordinate before mutating shared Git metadata, the canonical runtime checkout, integration state, runtime sync, or bootstrap/build resources.

## Lock Storage

CODE_CONFIRMED: Locks live under the shared Git metadata directory:

```text
<git-common-dir>/putpocket-locks/
```

For this local checkout, `putpocket-agent locks status` resolves the lock root to:

```text
/home/dyryu/putpocket_dataset_mining/.git/putpocket-locks
```

Lock files and pending request files are runtime coordination metadata and are not committed.

## Behavior

CODE_CONFIRMED: `putpocket-agent task start` acquires `git-metadata` and `task-start` locks before fetching, allocating a task id, creating an agent branch, and adding the worktree.

CODE_CONFIRMED: `putpocket-agent task integrate` acquires `git-metadata`, `integration`, `runtime-sync`, and `canonical-runtime` locks before fetch/push/runtime sync.

CODE_CONFIRMED: `putpocket-agent runtime sync` acquires `git-metadata`, `runtime-sync`, and `canonical-runtime` locks before fetch/pull/bootstrap doctor-only/receipt writing.

CODE_CONFIRMED: Mutating `bootstrap_sr.py` server2 and runpod-dev flows acquire `canonical-runtime` and `build` locks before environment, external, Docker, or native build mutation. Dry-run and doctor-only paths remain read-only and do not take the build lock.

CODE_CONFIRMED: Lock conflicts do not silently proceed. The command writes a pending request under `<git-common-dir>/putpocket-locks/pending/` and exits with `LOCK_HELD_PENDING_RECORDED`, including the blocking owner metadata.

CODE_CONFIRMED: Same-host stale locks are automatically removed only when their recorded PID no longer exists.

## CLI

CODE_CONFIRMED: Added:

```bash
putpocket-agent locks status
```

It reports `active_locks`, `pending_requests`, and `lock_root`.

CODE_CONFIRMED: Added `--wait-lock <seconds>` to:

```bash
putpocket-agent task start
putpocket-agent task integrate
putpocket-agent runtime sync
```

The default is immediate conflict reporting and pending receipt creation. `PUTPOCKET_LOCK_WAIT_SECONDS` can set a default wait when the CLI option is omitted.

## Limitations

INFERENCE: These are local/shared-gitdir advisory locks. They coordinate Agents sharing the same checkout/common Git directory or the same Network Volume checkout. They do not provide a distributed lock across independent clones on different machines.

INFERENCE: Pending requests are durable receipts, not an automatic worker queue. A later Agent or human must inspect and retry pending work after the blocking lock is released.
