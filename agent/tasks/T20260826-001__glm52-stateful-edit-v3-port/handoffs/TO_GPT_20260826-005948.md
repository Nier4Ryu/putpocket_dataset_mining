## New server architecture

The client scenario remains separate. The server consumes only a strict
token/cache manifest plus four namespaced request xargs. With no hook, ordinary
requests and ordinary prefix correctness are unchanged. With the hook active:

1. A donor request exactly matching the attested source prompt finishes; the
   scheduler registers its block objects under an opaque one-use handle and
   adds explicit block-pool references independent of prefix hashes.
2. A target request resolves that live handle and validates owner, one-use
   state, block object identity/refcount, source/target token counts and
   digests, tokenizer/serializer identity, vLLM/model/runtime identity, cache
   dtype/layout/layers/dimensions, alignment, edit coverage, mandatory rows,
   selector order, and exact recompute/reuse coverage.
3. The scheduler bypasses prefix lookup, allocates and zeros physical target
   slots through frozen boundary `H`, but schedules only exact recompute rows
   `R`. Deletions have no target slot; insertion and replacement targets are
   mandatory members of `R`.
4. The worker copies each unselected aligned donor row into the target main and
   packed-indexer cache on every declared layer. It then selects token IDs by
   exact `R` positions, applies those same absolute positions to `position_ids`
   and slot mapping, and synchronously verifies each physical slot against the
   current target block table. There is no full-prefill fallback.
5. Both sparse metadata builders virtualize the `|R|` rows as independent
   one-token decode lanes. Lane `p` shares the target block table and uses
   causal sequence length `p + 1`, so its sparse query attends to the full mixed
   target logical prefix while later rows remain masked. Native per-layer cache
   updates write only the exact target slots.
6. After the sparse forward, scheduler logical state is set to `H`, never
   `|R|`. The target must have `P > H`; a request ending at `H` fails closed.
   The first cached step must carry `num_computed_tokens == H`, and the worker
   verifies ordinary Q2 token IDs, absolute positions, and slots beginning at
   `H`. If Q2 allocates a new block, immutable attestation stays fixed while
   the refreshed current block table must extend the initial table by prefix.
   Sparse-patch and first-normal-continuation evidence are separate events.

The execution event records exact model input positions and token digest,
physical slot-map digest, donor and target block-table digests, copy counts,
layer-write digest, shifted-row count, and explicit
`full_target_prefill_executed=false`. The helper rejects `|R| == H` and rejects
any input-position/token/slot mismatch.
