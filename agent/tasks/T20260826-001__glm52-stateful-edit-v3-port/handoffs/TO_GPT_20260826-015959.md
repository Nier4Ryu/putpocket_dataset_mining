## API and CLI

The public Python API in
`src/putpocket_dataset_mining/stateful_edit_scenarios.py` provides:

- `validate_catalog()` / `validate_scenarios()`;
- `list_scenarios()`;
- `load_scenario()`;
- `filter_scenarios()`;

It uses JSON only and validates schema, schema/scenario SHA-256, deterministic
ID ordering, duplicate IDs/paths, indexed file completeness, cross-file

## Remaining client plumbing

The catalog intentionally does not implement:

1. tokenizer/chat-serializer resolution and message-span token mapping;
2. A1 generation/tool execution/Q2/repository-state freezing;
3. generic alignment and edit-operation generation;
4. mandatory dependency/implementation closure calculation;
5. outcome-independent importance capture, aggregation, tie-breaking, and
   budget resolution;
6. template-to-frozen-episode and donor/target server-manifest generation;
7. HTTP/OpenAI request plumbing proving `vllm_xargs` reach
   `SamplingParams.extra_args`;
8. true-path server packaging/start, donor lifetime, A2/tool loop, per-rank
   evidence collection, GPU validation, and fresh official evaluation.

The current replacement-only frozen episode schema must be extended before
multi-disjoint, insertion, or deletion templates can be resolved. Shifted reuse
must not be called RoPE-correct until the registered RoPE-aware server slice is
implemented and GPU-tested.
