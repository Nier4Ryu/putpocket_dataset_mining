# T20260826-001 live score-capture profile-batch correction

## Outcome and scope

RunPod query-sum attempt 5 reached the newly wired `DeepseekV2Model` batch
hook, but vLLM invoked that hook first during its synthetic memory-profile
forward. The synthetic position-zero batch was shorter than the frozen
2,105-token prompt, so the old unconditional count assertion stopped engine
startup before any request.

The default-OFF score hook now disarms any position-zero batch whose flattened
token count differs from the configured frozen prompt. Only an exact-count
batch can arm capture. Exact-count batches still fail closed unless input and
position shapes agree, absolute positions are exactly `0..P-1`, and the token
digest matches. A wrong or absent real prompt therefore cannot emit accepted
capture files; the runner/analyzer still rejects missing evidence.

This correction changes no inference, scheduling, cache-reuse, attention, or
indexer decision. The generated vLLM score overlay is unchanged. Only its
separately installed instrumentation module and bound package/document hashes
changed.
